## Problem

The research planner stops on assertion-count coverage, which suppresses useful fetches
even when the operator has flagged low settledness on a target and relevant URLs are
available in the last search results. Terrain:
[research-targeting-scouting.md](./research-targeting-scouting.md).

## Done When

- [x] The research prompt's only stop rule is a narrow escape valve: the model may return
      `stop` after a `fetch` that added assertions for the primary target and left no
      further relevant links; there is no coverage-based or budget-counting stop rule in
      the prompt (→ scouting F7, F18, F21, operator)
- [x] `DecidePlan` receives a per-target composite uncertainty signal from assertion-derived
      `half_width` and operator `DimensionRuling.settledness`, and uses it to pick the next
      target to dig into (→ scouting F2, F17, F20)
- [x] A resumed pass with low-settledness pins and available relevant URLs issues `fetch`
      calls and adds new assertions, not just `search` + `stop` (→ scouting F18, F19)
- [x] `DimensionRuling` stays operator-only: no model writes or auto-updates rulings (→
      scouting F16)
- [x] `DecidePlan`'s inputs are limited to what it actually needs to decide: no budget
      counters, no coverage summary, no fields the model never reasons over (→ operator)

## Approach
- Recompute per-target uncertainty from the current assertion set each turn using
  existing `TargetStats.half_width` math and the operator's `DimensionRuling.settledness`;
  the result is a deterministic ranking, not a stored time-series (→ scouting F17, F20)
- Blend assertion-derived uncertainty with operator `DimensionRuling.settledness`: a low-
  settledness pin raises urgency, a high-settledness pin suppresses it, an unrated target
  falls back to assertion-derived signal (→ scouting F20)
- Pass the *top-ranked* target into `DecidePlan` as `primary_target` — a directive, not a
  list for the model to reason over. Coverage counts and coverage summaries are no longer
  passed to the model at all; they added prompt noise without changing the decision now
  that ranking is deterministic (→ scouting F6, F21, operator)
- `DecidePlan`'s inputs are the minimal set the model actually reasons over:
  `company_name`, `opening_title`, `rubric_text`, `primary_target`, `last_context_text`,
  `prior_queries`. Dropped `opening_id` (never used in reasoning), `targets_covered` /
  `coverage_summary` (coverage no longer drives decisions), and `turns_used` /
  `turn_budget` (budget is dispatcher-owned, never model-owned) (→ operator)
- Stop is a narrow escape valve, not a general-purpose decision: the model may return
  `stop` only when the last action was a `fetch` that added assertions for the primary
  target and the fetched page left no further relevant links to follow. A search with no
  fetchable hit, or a fetch that added nothing, is never a stop signal — those call for a
  different search or another source, not quitting. Turn-budget exhaustion remains the
  dispatcher's independent, deterministic termination condition; the model never sees or
  reasons about the budget (→ scouting F12, F18, F21, operator)
- Keep the `search`/`fetch` split: only `fetch` extracts assertions; the planner uses the
  top target to choose which promising URL to fetch while budget remains (→ scouting F19)
- Sticky target per turn: once a target is selected, the planner stays on it until it
  either exhausts the available leads (no relevant URL in `last_context`) or hits a
  per-target action cap seeded from `scoring.yaml`. This prevents search/fetch thrash
  where the ranking would flip mid-chain before a lead is followed (→ operator, F22)
## Not Doing
- Algorithmic cross-opening research-pass bandit — this is the *within-opening* planner;
  the bandit is a separate future node (→ parent §Not Doing, scouting F10)
- Tuning the blend weights, thresholds, or per-target cap off one observation — build
  the signal, exercise it, then calibrate (→ scouting F14, F22)
- Per-event trace rows in the DB or a logged history of the composite signal — the
  ranking is recomputed deterministically each turn from the current assertions and
  rulings; no stored decision history is needed (→ operator)
- Multi-action chains or sub-loops beyond one `search`/`fetch` per turn with a sticky
  target — action set stays small; the model may follow a link from a fetched page by
  issuing another `fetch`, but the dispatcher does not add a `continue` action or a
  nested loop (→ operator)

## Recalibrate When

- The composite signal keeps steering the planner to targets the operator has already pinned
  with high settledness, or away from low-settledness pins — the blend is wrong
- The planner still refuses to issue a `fetch` despite available relevant URLs and budget
  headroom — the signal isn't reaching the action choice
- After several real passes the operator still has to manually bump budgets to get useful
  work — the blend weights need a `scoring.yaml` dial and tuning (→ scouting F14, F15)

## Agreed
- The prompt's only stop rule is the narrow mined-out-lead escape valve; turn-budget
  exhaustion is enforced entirely by the dispatcher and never appears in the prompt (→
  scouting F21, operator)
- Use a composite uncertainty signal that reads both assertion-derived `half_width` and
  operator `DimensionRuling.settledness`, not one or the other (→ scouting F20, operator)
- `DimensionRuling` stays operator-only; models do not generate or update rulings (→
  scouting F16, operator)
- Turn budget remains the cheap-pass lever; no additional initial/lifetime/coverage dials
  (→ parent §Agreed, operator)
- Pass the planner a single sticky `primary_target` derived from deterministic ranking,
  with a `scoring.yaml`-seeded per-target action cap to prevent mid-chain thrash; the
  model may follow a link from a fetched page by issuing another `fetch` on its own
  (→ operator, F22)
- `DecidePlan` only receives fields it reasons over; audit-trail fields (`turns_used`,
  `turn_budget`, `targets_covered`, etc.) stay in the dispatcher's trace snapshot for
  debugging but are not part of the model's prompt (→ operator)
