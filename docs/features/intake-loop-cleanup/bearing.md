## Problem

The intake-to-research pipeline has outgrown its names. "Transcript" now describes both a raw JSONL execution trace and the DB evidence ledger, `loop/` is a weak name for a bounded research/dispatch context, `_data_dir()` is duplicated, and BAML source and generated client are misplaced and double-nested. This cleanup makes the code say what it does.

## Done When

- [ ] `research_trace` replaces "transcript" in file names, function names, `events.py` models, and the `Opening.research_trace_id` field/DB column; no committed file or symbol contains `transcript` in this context.
      → `grep -R "transcript" src/screen/intake src/screen/research src/screen/store tests/` returns only unrelated hits; `uv run python -m pytest` passes.
- [ ] `src/screen/loop/` is renamed to `src/screen/research/` and all imports are updated.
      → `uv run python -m pytest` passes.
- [ ] `baml_src/` and `baml_client/` are siblings under `src/screen/`, the generated client is a single package at `src/screen/baml_client/` (no `baml_client/baml_client`), and `loop.baml` is renamed to `research.baml` (operator: didn't want to wonder what it's about).
      → `ls -d src/screen/baml_src src/screen/baml_client` succeeds and `test -d src/screen/baml_client/baml_client` fails.
- [ ] `_data_dir()` has one implementation used by both CLI and API.
      → `grep -n "def _data_dir" src/screen/**/*.py` returns one hit.
- [ ] The self-claimed "Wall 6" invariant is removed from the trace module and replaced by an honest interim note.
      → `grep -n "Wall 6" src/screen/intake/transcript_io.py` (post-rename: the trace module) returns nothing; `types.py:132` and `store/repo.py:47`'s real Wall 6 (Assertions append-only) are untouched.

## Approach

- Rename the transient trace to `research_trace` and the bounded context to `research/` (→ scouting F4, F9, N1, N2). Keep the file-based trace append-only but explicitly interim, not the evidence ledger. `Opening.transcript_id` renames to `Opening.research_trace_id`, including the DB column in `migrations/0001_create_domain_tables.sql` — edited in place, no migration script, data is disposable (operator).
- Move BAML source to `src/screen/baml_src/`, sibling to the generated `src/screen/baml_client/`, by setting `output_dir` to `..` relative to the new `baml_src/` (→ scouting F11, N4; operator: siblings under `screen`, BAML docs don't dictate otherwise). Regenerate; do not hand-edit generated files.
- Collapse `_data_dir()` into a single shared helper called by both `intake/cli.py` and `api/app.py` (→ scouting F8).
- Remove the self-claimed "Wall 6" invariant from the trace module and replace it with a comment stating the trace is an interim resumability target, not the evidence ledger (→ scouting F3).
- Leave the DB-resumability design untouched; this is a rename and relocate pass, not a persistence redesign (→ scouting N3).

## Not Doing

- Designing a real replay/resume feature or a `ResearchPass` DB table — deferred until there is a consumer (→ scouting N3).
- Changing BAML schema definitions, LLM client wiring, or model/provider choices.
- Building application tracking, auto-apply, or queue UI.

## Testing

Test-first by default. Exempt:
- `src/screen/baml_client/` — generated by BAML codegen; verified by `ls` and import tests, not by hand-written unit tests.

## Recalibrate When

- A test or import failure reveals a real consumer of the old `transcript`/`loop` names outside the renamed modules.
- Moving or flattening BAML requires editing `.baml` files beyond the generator `output_dir` line.
- We discover a concrete replay/resume requirement during the rename; stop and route to a new bearing.

## Agreed

- `research_trace` replaces `transcript` for the raw execution trace — not `pass_trace`, `run_log`, or `execution_log` (→ scouting N1).
- `research/` replaces `loop/` for the research/dispatch bounded context — not `pass/`, `dispatch/`, or `agent/` (→ scouting N2).
- BAML files move now: `baml_src/` → `src/screen/baml_src/`, sibling to `src/screen/baml_client/` (not `src/baml_src/` — operator confirmed siblings under `screen` since BAML docs don't require otherwise), flattening the client via `output_dir ".."` (→ scouting N4, F11).
