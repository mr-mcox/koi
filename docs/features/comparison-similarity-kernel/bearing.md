## Problem

The operator's comparison attention is being spent on near-duplicate dimension pairs — back-to-back `location` comparisons across different companies whose digests all say "US remote full-time" — instead of on novel, judgment-heavy dimensions. `location` is opening-level, so two different companies' near-identical remote postings get zero correlation today; the picker surfaces them as high-variance because nothing tells it they're analogous. The operator wants previous rulings to carry forward so comparison energy goes where it's novel. Terrain: [scouting.md](./scouting.md)

## Approach

- **Removed (2026-10-02): the coarse cosine pre-filter.** The first real `/compare` session surfaced a `location` pair Jev should have unanimously ruled a tie, but Jev was never called — the fastembed cosine gate (`candidate_pairs`, τ=0.85) rejected it first. Measured against the live pool (scouting F-SC3): only 1 of 63 `location`-digested openings ever clears τ=0.85, because digest *text* varies even when rubric-relevant content is identical — exactly the gap Jev was built to close. The coarse gate's cost justification (avoid firing Jev across an O(n²) bulk scan) never applied to the live flow, which only ever evaluates one picker-suggested pair at a time; there was no fan-out to economize on, and Jev is cheap enough that there's nothing worth pre-filtering for a single pair. `_provisional_comparison_for_suggestion` now calls Jev directly on every suggested pair with a cached digest on both sides — no embedding, no cosine, no threshold. `fastembed`, `src/screen/embed/`, `similarity_tau`, and the bulk `provisional_verdicts()` composer (already unwired from anything live) were removed entirely, not just unused — see decisions.md S14 addendum.
- Per-dimension, same-dimension only, for **every scored dimension** (including `domain`): for each opening pair the picker suggests next, Jev rules that pair `left/right/tie` with its own calibrated confidence; below `jev_confidence_threshold`, **none** — the pair surfaces to the operator exactly as if Jev didn't exist. On `domain` the tie correlates *factual* domain similarity; the operator's coolness judgment stays the load-bearing signal, never guessed by the tie (→ scouting F10, F11, F20, F21). **Confidence gate — Jev's calibrated confidence is the only gate; there is no upstream filter ahead of it.**
- Provisional verdicts are produced **live by Jev** per comparison in the flow — Jev as a short-circuit before the operator sees a comparison. `fit_pairwise` is no longer called with a pre-computed tie list; the fit consumes Jev's verdict + confidence directly. An operator ruling displaces a provisional verdict on that pair — "until I override" is literal, not a weight competition (→ scouting F15α, F18). **Live generation — the offline kernel is retired.**
- Picker suppression is **hard exclusion**, revised from the original emergent-via-covariance design: measurement (two independent reconfirmations, pre- and post-Jev-pivot) showed the covariance nudge alone cannot overcome a high-weight dimension's pull, and the operator's actual requirement ("I should not see it again") is stronger than "it's somewhat less likely to surface." `select_comparison` computes, per dimension, the set of pairs whose *latest* comparison is `provenance=provisional` and excludes those (pair, dimension) triples from `_best_dimension_for_pair` entirely — not down-weighted, not in the running. An operator ruling is never excluded this way (only down-weighted via variance decay, the pre-existing behavior) — only a provisional row triggers exclusion, and only until an operator ruling on that exact pair displaces it (→ scouting F19, operator conversation 2026-10-01).
- The exclusion is paired with a visible, overridable surface so it stays W5-compatible (retrieve-and-show, never a silent auto-close): `/compare/review` lists every un-overridden provisional comparison; opening one routes into the ordinary compare form for that exact pair, and submitting a ruling there is the override (no new override mechanism — it's the same dedup-to-latest reduction that already displaces a provisional row with a later operator one).
- The pre-screen pass that produces these provisional verdicts runs as a `BackgroundTasks` job triggered by `GET /compare`, polled by the browser (`/compare-status`, htmx `every 1s`) exactly as `/batch`/`/batch-status` already does for research batches — this is the UX answer to Jev's per-call latency (operator: "it could also be some sort of polling page… I'd like some way to see that jev is doing something"), not a separate decision.
- A `decisions.md` entry records provisional **similarity ties and wins** on the `precedent_matched` rung, naming what it rules out (auto-closing-without-override is out; auto-tie-win-with-override is in if scoped to new pairs) (→ scouting F8, W5)

## Not Doing

- Cross-dimension similarity — a `location`-similar pair is not evidence of a `mission`- or `comp`-similar pair; whole-posting-duplicate dedup is an intake concern, not scored here (→ scouting F11, F20)
- A separate picker-suppression layer that duplicates the fit's own comparison bookkeeping — the exclusion set is computed from `comparisons_by_target` the picker already receives, not a new data source (→ scouting F19)
- Auto-closing judgments / trusting provisional verdicts without override — agreement-rate measurement (OQ6) and any auto-close argument are deferred until a real corpus exists (→ scouting F8, W5, OQ6). **Auto-tie-win is in for new pairs (no override needed yet); existing pairs are validated/overrideable — consistent, not a violation.**
- `PrecedentLookup` (auto-filling assertions on unexamined dimensions) — this fabricates comparison ties between evidenced openings, not assertions on unexamined ones (→ scouting F9)
- A pool-wide covariance kernel inside `rank_pool` (O(n²) per read) — provisional verdicts inject at the comparison layer, not as a live scorer kernel (→ scouting F12, F13)

## Recalibrate When

- If provisional ties flatten the live queue (rank bands collapse, too many openings tied together), stop — `jev_confidence_threshold` is too low; re-tune rather than ship the flattening
- If the dedup-to-latest step (F18) changes live rank order for pairs with multiple *operator* re-judgments, stop — check whether re-judgments were meant to accumulate or replace before relying on the new behavior
- If an operator override needs to propagate through the similarity graph (ruling on A~B should weaken A~C), stop — that's divergence-propagation, out of scope here; decide whether to expand
- If calling Jev on every suggested pair (no coarse pre-filter) turns out to add real cost at scale — a pool large enough that many consecutive suggestions all miss Jev's confidence gate — stop and reconsider a pre-filter; not measured as a problem yet (→ decisions.md S14 addendum)
- If the live per-pair Jev call adds noticeable latency to `/compare`, stop — the polling pre-screen UX (`/compare-status`) is the current mitigation; revisit if it's not enough

## Agreed

- `fastembed` + all-MiniLM-L6-v2 ONNX, not sentence-transformers/torch — torch's hundreds-of-MB weight is disqualifying for a feather-light project (→ scouting F14, F17). **Superseded 2026-10-02: the coarse embedding gate this served was removed entirely — see Approach.**
- F10iii threshold + graded-above-threshold, not a cliff (i) and not threshold-free grading (ii) — boilerplate clusters hard at the top, vague similarity shouldn't count (→ scouting F10). **Superseded 2026-10-02: this decided the coarse cosine gate's shape, which was removed; Jev's own confidence threshold (`jev_confidence_threshold`) is the only threshold left, and it already is graded-above-threshold.**
- F15α per-comparison provenance column + dedup-to-latest, not on-the-fly generation (β) — "until I override" is literal displacement, and the dedup closes a gap the docstrings already claim (→ scouting F15, F18). **Revised: `comparison_beta` (operator-owned per-provenance dial) → `jev_confidence_threshold` (operator-owned confidence dial). Jev owns its beta internally; the operator owns the gate value, not the beta — measure-before-model preserved.**
- Same-dimension only, not cross-dimension — a location-similar pair is not evidence of a mission/comp-similar pair (→ scouting F11, F20)
- Settledness is the existing rank-band width, not a new workflow state — narrow band = more settled (→ scouting F16)
- Provisional ties carry less weight than operator rulings — "doesn't need too much weight" (→ scouting F9, F15)
